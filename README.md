# SpermPipeline — от видео до кластеров одним приложением для Windows

```
SpermPipeline
  00 КАДРЫ         .mpg → кадры (ffmpeg) → отрезки «начало-конец» + _rejected (GET SEQUENCES IN ORDER FROM VIDEO.py)
  0 TRACKMATE      кадры → ваша Fiji без окна: 8-bit → Gaussian → контраст (B&C) → Find Maxima (Single Points)
                   → TrackMate LoG + LAP → CSV спотов и треков (шаги Fiji-плагина Sperm_Tracking_Pipeline)
  1 ТАБЛИЦЫ        оформление экспортов TrackMate (.csv) — вместо макросов Excel
  2 ФИЛЬТРАЦИЯ     супер-фильтрация каждого отрезка: сшивка → разрез у границ → свап коллизий → фильтр по длине
  3 СКЛЕЙКА        отрезки одного видео в одну таблицу (бывший CONCATTING.py)
  4 CASA           VCL, VSL, VAP, LIN, STR, WOB, ALH, BCF по точкам итоговых треков (casa_metrics.py v2)
  5 КЛАСТЕРИЗАЦИЯ  HDBSCAN по VAP + STR + LIN → IM / RP / SP / NP (hdbscan casa 2d.py)
```

Алгоритмы и значения по умолчанию — ваши скрипты без изменений логики (копии лежат в `original/`,
отличия помечены в коде меткой `[SpermPipeline]`). Любой шаг можно выключить и начать с середины:
например, только кластеризация по готовой папке `CASA TRACKS v2`.

## Запуск

| Что | Как |
|---|---|
| Окно приложения | `run_app.bat` (берёт Python из `pythonProject1\.venv`, где всё уже установлено; иначе Python из PATH) |
| Поставить пакеты и проверить | `install_and_selftest.bat` |
| Собрать .exe без Python | `build_exe.bat` → `dist\SpermPipeline\SpermPipeline.exe` (или скачать готовый со страницы Actions репозитория) |
| Самопроверка | `SpermPipeline.exe --selftest` / `python SpermPipeline.py --selftest` (синтетическое видео, весь путь) |

## Шаг 00: нарезка видео

Ваш `GET SEQUENCES IN ORDER FROM VIDEO.py` без изменения логики и порогов (вкладка «Нарезка»): ffmpeg режет
`01.mpg` на `frame_00001.png …` в папку `1 video`, кадры с яркостью/разбросом/шумом вне порогов уходят в `_rejected`,
хорошие куски длиннее `MIN_SEGMENT_LEN` (минус `TRIM` с краёв) — в папки `начало-конец`. Уже нарезанные видео заново
не режутся, поэтому можно указать «Папку для кадров» = ваша `SEQUENCES IN ORDER`. Внимание: если поменять пороги,
уже разложенное видео **не переразложится** — удалите его папку кадров, и оно нарежется заново.

## Шаг 0: TrackMate без окна

Нужна установленная Fiji (путь к `ImageJ-win64.exe` — на вкладке «Запуск»; пусто — ищется в `C:\Fiji.app` и т.п.).
Приложение запускает её в фоне со встроенным Jython-скриптом. Отрезок — как в плагине: **папка с кадрами**
(`.png/.jpg/.bmp/.tif`, открывается как Image Sequence) или файл `.tif/.tiff/.avi`; имя начинается с диапазона кадров.
Папка с отрезками = видео, можно указать и папку с несколькими видео: `SEQUENCES IN ORDER\1 video\1230-1640\frame_01230.png`.
Папки на `_` (`_rejected`) пропускаются. `.mpg` Fiji без FFmpeg не читает — указывайте папки с кадрами.
Координаты — в пикселях, время — в кадрах. Параметры — вкладка
«TrackMate»: **один набор на все видео**, без подгонки под отрезок. Проверка на синтетическом видео:
`python tools/fiji_check.py "C:\Fiji.app\ImageJ-win64.exe"`.

**Несколько Fiji одновременно** («Fiji одновременно» на вкладке «Запуск»). Одна Fiji считает отрезки по очереди и
занимает процессор лишь частично, поэтому отрезки делятся на N Fiji поровну по объёму; у каждой свой журнал
(`_fiji_журнал.txt`, `_fiji_журнал_2.txt` …), 75 % ОЗУ делятся поровну, потоки процессора тоже. Результат тот же,
что у одной Fiji (проверяется в CI: те же споты, те же треки, те же признаки; отличаются только номера ID). Предел — память: отрезок открывается как RGB-стек,
~6 байт на пиксель кадра (1000 кадров 720×576 ≈ 3 ГБ). Если самый длинный отрезок не влезает в долю одной Fiji,
приложение само запустит меньше Fiji и напишет об этом в журнале. По умолчанию: ~3 потока и ~4 ГБ на Fiji
(i5-10400F, 16 ГБ → 4).

**Площадь объекта в Find Maxima** (три поля на вкладке «TrackMate», по умолчанию выключено). Максимум становится
точкой, только если яркое пятно, в котором он лежит, имеет площадь от «не меньше» до «не больше» (px, 0 — не
проверять). Пятно — связная область пикселей ярче «уровня» на картинке перед контрастом (после Gaussian); уровень 0
значит «ярче Контраст: Min». Крупные пятна — сгустки и большие клетки, самые мелкие — мерцание у порога. В журнале
на каждый отрезок пишется, сколько максимумов убрано и какая площадь у оставленных. На кадрах видео 1 (контраст
230–240, sigma 2): при уровне 0 одиночные головки 1–70 px, слившиеся сгустки 255–426 px, но часть сгустков
распадается на мелкие пятна и проходит; при уровне 210 одиночные 26–280 px, сгустки 540–2000 px.

## Из Fiji-плагина (по желанию)

Плагин на шаге 5 вызывает `python.exe <скрипт> config.json` с папками `spots_dir`, `tracks_dir`, `output_dir`.
Укажите в плагине вместо `super_filtration_with_excel_10_files.py` файл **`SpermPipeline.py`** — он выполнит шаги 2–5
целиком (параметры берутся из тех, что сохранены в окне приложения). Шаг 6 плагина (старый
`SPERM_Clasterization-2.py` с UMAP) больше не нужен. Одна папка спотов = одно видео.

## Папки результатов

Папка на каждое видео, имя — как у файла видео (`01.mpg` → `01`; старые папки кадров `1 video` тоже
становятся `01`, если задана папка с .mpg). Сводка по всем видео — в `_ВСЕ ВИДЕО`.

```
<папка результатов>\
  01\
    00 КАДРЫ\<отрезок>\           кадры (если шаг 00 включён и «Папка для кадров» пуста); брак — в _rejected
    0 TRACKMATE\                  <отрезок>_spots.csv, <отрезок>_tracks.csv, _параметры TrackMate.json
    1 ТАБЛИЦЫ\                    оформленные *_spots.xlsx / *_tracks.xlsx
    2 ФИЛЬТРАЦИЯ\                 <отрезок>proc.xlsx + <отрезок>_журнал.txt (весь вывод фильтра: сшивки, свапы)
    3 СКЛЕЙКА\01.xlsx             таблица треков видео
    4 CASA TRACKS\01.xlsx         то же + столбцы CASA_* (это вход кластеризации)
    4 CASA SPOTS\                 точки итоговых треков
    5 КЛАСТЕРИЗАЦИЯ\              01_scatter.png, итог 01.xlsx (строка видео, кластеры, параметры, треки с метками)
  02\ …
  _ВСЕ ВИДЕО\
    summary_all_videos.xlsx       проценты IM / RP / SP / NP по всем видео (одна строка — одно видео)
    tracks_labeled.xlsx           все треки всех видео с метками
    _проверка отрезков.xlsx       по каждому отрезку: файлы, число треков, ошибки, исправлены ли столбцы
    настройки <дата>.json         все параметры прогона — чтобы результат можно было повторить
    журналы Fiji\                 _fiji_журнал.txt (_2, _3 … при нескольких Fiji)
```

Вход для шагов 2–4: папка, где лежат `*spots*.xlsx` (видео = эта папка или каждая её подпапка, например
`BEFORE FILTER SPOTS\10 video`). Отрезок = диапазон кадров в начале имени файла (`1223-1622_allspots (1).xlsx` → `1223-1622`).
Два файла спотов на один отрезок в одной папке — ошибка (иначе треки посчитаются дважды).

## Что изменено по сравнению со скриптами (и почему)

1. **Макросы → `tables.py`.** Шапка, описания, Frame_range, закрепление, фильтр — как в макросах. Но столбцы берутся
   **по имени**, а не по позиции: позиционная вставка шапки и сделала сдвинутые столбцы в спотах видео 1, 2, 15.
   Числа читаются без Excel, поэтому RADIUS = 2.5 больше не превращается в дату.
2. **Фильтрация отдаёт точки итоговых треков** — CASA считается по ним за один проход. Раньше casa_metrics.py
   ради этого заново прогонял весь фильтр.
3. **Сдвинутые столбцы спотов** (как у видео 1, 2, 15) исправляются автоматически перед фильтрацией (`fix_shifted` из casa_metrics.py).
